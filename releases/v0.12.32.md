# v0.12.32

## New Features 🎉

* **Add additional persona fields to flows** ([#3865](https://github.com/pluralsh/console/pull/3865)) by @JohnBlackwell

  > Additional persona fields have been added to the flows feature, enabling more granular control over permissions and the ability to start workbench jobs directly from the flow detail page. This enhancement allows users to manage flow permissions more effectively and streamline their workflow processes, improving overall user experience and operational efficiency.

* **bootstrap ES log rollover ILM and write alias** ([#3871](https://github.com/pluralsh/console/pull/3871)) by @zreigz

  > Elasticsearch now supports log rollover and index lifecycle management (ILM) through a new write alias, enhancing the management of log data. This update introduces policies for automatic index rollover based on size and age, ensuring efficient storage and retrieval of logs while preventing conflicts with existing write indices. These improvements streamline log management, making it easier for users to maintain performance and compliance in their Kubernetes environments.

* **Compatibility Matrix Update 2026-07-19** ([#3879](https://github.com/pluralsh/console/pull/3879)) by @app/github-actions

  > The compatibility matrix has been updated to include version 2.8.0 of the External Secrets chart, which introduces several significant enhancements. Key features include a new `aggregateToAdmin` toggle for RBAC aggregation, optional `networkPolicy` support for better security configurations, and `webhook.startupProbe` support to manage slow-starting clusters. These updates improve the flexibility and reliability of deploying External Secrets in Kubernetes environments, ensuring users can better manage access controls and resource availability.

* **Docker/OCI workbench integration** ([#3882](https://github.com/pluralsh/console/pull/3882)) by @michaeljguarino

  > The integration of Docker and OCI registries into the Workbench tool enhances the ability of agents to inspect and manage container images directly from the Plural Console. Users can now search for tags and fetch manifests from various registries, including Docker Hub and GitHub Container Registry, streamlining the deployment process and improving workflow efficiency. This feature supports both public and private registries, allowing for flexible authentication options, which is crucial for teams working with diverse container environments.

* **Compatibility Matrix Update 2026-07-21** ([#3883](https://github.com/pluralsh/console/pull/3883)) by @app/github-actions

  > The compatibility matrix for the EKS add-ons has been updated to include new versions and their corresponding Kubernetes compatibility. Notably, versions such as `v1.0.4-eksbuild.1` and `v1.36.0-eksbuild.13` now support multiple Kubernetes versions, enhancing user flexibility in selecting compatible add-ons for their clusters. This update ensures that users can leverage the latest features and improvements while maintaining compatibility with their existing Kubernetes environments.

* **Compatibility Matrix Update 2026-07-21** ([#3884](https://github.com/pluralsh/console/pull/3884)) by @app/github-actions

  > The compatibility matrix has been updated to include version 3.4.0 of the AWS EFS CSI Driver, which is now compatible with the latest Kubernetes releases. This update ensures users can leverage the latest features and improvements of the driver without facing compatibility issues, thereby enhancing the stability and functionality of their Kubernetes deployments.


## Bug Fixes 🐛

* **chore: Update ESLint config, Yarn version and fix vulnerabilities** ([#3869](https://github.com/pluralsh/console/pull/3869)) by @maciaszczykm

  > The ESLint configuration has been updated alongside the Yarn version, enhancing code quality and security by addressing identified vulnerabilities. This update ensures that developers benefit from the latest linting rules and package management improvements, which can lead to a more stable and maintainable codebase.

* **fix: Fix health score heatmap flyover for clusters outside the table page** ([#3880](https://github.com/pluralsh/console/pull/3880)) by @maciaszczykm

  > The health score heatmap flyover for clusters now correctly displays information for clusters that are not on the current table page. This enhancement improves user experience by ensuring that users can access detailed health metrics for all clusters, regardless of their current view, thereby facilitating better monitoring and management of Kubernetes resources.

* **fix(provider): update Ready method to remove TTL check** ([#3886](https://github.com/pluralsh/console/pull/3886)) by @floreks

  > The Ready method in the provider has been updated to eliminate the time-to-live (TTL) check, ensuring that the provider remains ready as long as a valid configuration is present. This change enhances the reliability of the observability proxy by allowing it to continue functioning with cached configurations, even if they become stale, which is crucial for maintaining uninterrupted service in production environments.
