# v0.12.40

## New Features 🎉

* **chore: Enable strict type checking in design system** ([#3979](https://github.com/pluralsh/console/pull/3979)) by @maciaszczykm

  > Strict type checking has been enabled in the design system, enhancing code reliability and maintainability by catching type-related errors during development. This change improves the overall developer experience, ensuring that components adhere to defined types, which can lead to fewer runtime errors and a smoother integration process. Additionally, a new Chromatic workflow has been introduced for publishing Storybook, allowing for automated visual testing and documentation of UI components with each push to the design system.

* **Compatibility Matrix Update 2026-08-24** ([#4046](https://github.com/pluralsh/console/pull/4046)) by @app/github-actions

  > The compatibility matrix has been updated to version 88.5.4, which includes significant dependency updates for kube-state-metrics and Grafana. Users can expect new or changed metrics from kube-state-metrics version 8.4.0 and various upstream fixes from Grafana version 12.11.2, enhancing the overall functionality and reliability of the kube-prometheus-stack.

* **implement policy + binding policy k8s operator CRDs** ([#4047](https://github.com/pluralsh/console/pull/4047)) by @zreigz

  > New Custom Resource Definitions (CRDs) for Policy and Binding Policy have been implemented, enhancing the Plural Console's capabilities for Kubernetes resource management. These CRDs allow users to define and enforce policies on resources based on specified criteria, facilitating automated policy application and drift detection. This improvement streamlines governance and compliance processes, making it easier for teams to manage their Kubernetes environments effectively.

* **chore(kubernetes): update tracked version to 1.36.4** ([#4048](https://github.com/pluralsh/console/pull/4048)) by @app/plural-copilot

  > The tracked Kubernetes version has been updated to 1.36.4, ensuring users benefit from the latest features, improvements, and security patches. This update is crucial for maintaining compatibility and leveraging enhancements in the Kubernetes ecosystem.

* **chore: Disable AI chat when workbenches exist** ([#4049](https://github.com/pluralsh/console/pull/4049)) by @maciaszczykm

  > AI chat functionality has been disabled in the Plural Console when workbenches are present. This change ensures that users are directed to manage their workbenches first, streamlining the user experience and preventing potential confusion when interacting with AI features in the presence of workbench-related tasks.

* **Custom mcp servers in agentruntime, and model + provider persistence** ([#4050](https://github.com/pluralsh/console/pull/4050)) by @michaeljguarino

  > The latest update introduces the ability to configure custom MCP (Managed Control Plane) servers within the agent runtime, enhancing flexibility in managing AI agent operations. Additionally, it implements persistence for models and providers, ensuring that configurations are retained across sessions. This change significantly improves the user experience by allowing for tailored setups and consistent performance in AI-driven workflows.

* **Compatibility Matrix Update 2026-08-25** ([#4052](https://github.com/pluralsh/console/pull/4052)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions for several components, such as EKS and kube-proxy, enhancing support for Kubernetes versions 1.30 through 1.36. This update ensures users can leverage the latest features and improvements in their Kubernetes deployments, promoting better stability and performance across their environments.

* **Compatibility Matrix Update 2026-08-25** ([#4053](https://github.com/pluralsh/console/pull/4053)) by @app/github-actions

  > The compatibility matrix has been updated to include support for Kubernetes version 1.36 across multiple components, including the AWS EBS CSI Driver, AWS EFS CSI Driver, and AWS Load Balancer Controller. This enhancement ensures that users can leverage the latest Kubernetes features and improvements, maintaining compatibility with their existing deployments. Keeping the compatibility matrix current is crucial for users to make informed decisions about upgrading their Kubernetes environments and utilizing the latest functionalities.

* **feat(deployment-operator): implement monty-based python interpreter for values templating** ([#4054](https://github.com/pluralsh/console/pull/4054)) by @floreks

  > The deployment operator now supports a Monty-based Python interpreter for values templating, allowing users to utilize Python scripts directly within their Helm charts. This enhancement provides greater flexibility and power in managing Kubernetes deployments, enabling more complex templating scenarios and improving the overall user experience in defining application configurations.

* **feat: Workbench policy enforcement** ([#4055](https://github.com/pluralsh/console/pull/4055)) by @maciaszczykm

  > Workbench policy enforcement has been enhanced with the introduction of a new Rego language support in the code editor, allowing users to define and enforce policies more effectively. This update includes a dedicated UI for managing policies and constraints, improving the overall security posture of Kubernetes deployments by facilitating better governance and compliance checks. Enhanced visual themes for Rego syntax in the editor further streamline the development experience, making it easier for users to write and review policies.

* **Compatibility Matrix Update 2026-08-26** ([#4058](https://github.com/pluralsh/console/pull/4058)) by @app/github-actions

  > The compatibility matrix for the EKS add-ons has been updated to include new versions and their respective Kubernetes compatibility ranges. Notably, several add-ons now support Kubernetes versions 1.33 through 1.36, ensuring users can leverage the latest features and maintain compatibility with their existing clusters. This update enhances the flexibility and reliability of deployments on EKS, allowing for smoother upgrades and better support for various Kubernetes versions.

* **Compatibility Matrix Update 2026-08-26** ([#4059](https://github.com/pluralsh/console/pull/4059)) by @app/github-actions

This change ensures that users can continue to utilize these versions with Kubernetes without facing immediate obsolescence, providing more time for migration and updates.

* **Polish Pure Light mode surfaces without changing dark mode** ([#4061](https://github.com/pluralsh/console/pull/4061)) by @wailingwombat

  > The update enhances the Pure Light mode of the Plural Console by refining the visual elements without altering the existing Dark mode. Key components, such as buttons and cards, now feature improved background colors and hover effects, ensuring a more cohesive and visually appealing experience for users in Light mode. This change is significant as it enhances usability and aesthetics, making the interface more intuitive and engaging for users who prefer a lighter theme.

* **Compatibility Matrix Update 2026-08-27** ([#4063](https://github.com/pluralsh/console/pull/4063)) by @app/github-actions

* **Compatibility Matrix Update 2026-08-27** ([#4064](https://github.com/pluralsh/console/pull/4064)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions for both Big Bang and Vector. Big Bang now supports version 3.31.1, which includes an upgrade to the Keycloak chart (from 7.2.2-bb.1 to 7.3.0-bb.0), potentially introducing breaking changes that users should review before upgrading. Additionally, Vector has been updated to version 0.58.0, which is a security-focused release that may include breaking changes; users are advised to check the release notes for details.

* **feat: Add copy to user prompt message in workbenches** ([#4065](https://github.com/pluralsh/console/pull/4065)) by @maciaszczykm

  > The user prompt message in workbenches has been enhanced to include a timestamp, providing users with context on when the prompt was generated. This improvement allows for better tracking and understanding of job activities, making it easier for users to manage and reference their workflows effectively. Additionally, a copy-to-clipboard feature has been added, streamlining the process of sharing prompt content directly from the interface.

* **small light mode tweaks** ([#4066](https://github.com/pluralsh/console/pull/4066)) by @michaeljguarino

Key updates include refined button colors for better visibility, adjustments to the progress bar's track color for improved contrast, and subtle border modifications across various components. ## Bug Fixes 🐛

  > Search functionality within the flows component has been enhanced to maintain search parameters when navigating back through the application. This improvement ensures that users can return to their previous search results seamlessly, providing a more intuitive and efficient experience when managing flows.

* **fix manifest cache** ([#4056](https://github.com/pluralsh/console/pull/4056)) by @zreigz

  > The manifest cache has been improved to ensure that missing directories are properly handled, allowing the system to refetch manifests when necessary. This fix enhances the reliability of the deployment operator by preventing errors related to missing cache directories, ultimately leading to smoother service deployments and updates.

* **hide stale flow results while search is loading** ([#4057](https://github.com/pluralsh/console/pull/4057)) by @JohnBlackwell

  > Stale flow results are now hidden while the search is loading, enhancing the user experience by preventing outdated information from displaying during search operations. This change ensures that users only see relevant results, reducing confusion and improving the overall efficiency of the search functionality.

* **fix: add musl build tags to Dockerfiles for compatibility with monty** ([#4073](https://github.com/pluralsh/console/pull/4073)) by @floreks

  > Musl build tags have been added to several Dockerfiles within the deployment operator, enhancing compatibility with the Monty environment. This change ensures that applications built using these Dockerfiles can run smoothly on systems that rely on musl instead of glibc, improving deployment flexibility and reliability for users operating in diverse environments.
