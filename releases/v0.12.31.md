# v0.12.31

## New Features 🎉

* **feat: Stacks Pulumi support** ([#3820](https://github.com/pluralsh/console/pull/3820)) by @maciaszczykm

  > Pulumi support has been added to the Stacks feature, enabling users to manage infrastructure as code using Pulumi alongside existing Terraform capabilities. This enhancement allows for a more versatile approach to stack management, providing users with additional options for deploying and configuring their applications in Kubernetes environments. The integration includes updated workflows and UI components, ensuring a seamless experience for developers utilizing Pulumi in their infrastructure setups.

* **Implement lambda + http actions for workbenches** ([#3848](https://github.com/pluralsh/console/pull/3848)) by @michaeljguarino

  > Lambda, Cloud Run, and Azure Function actions have been integrated into the workbench feature, allowing users to invoke serverless functions directly from their workbench configurations. This enhancement streamlines the process of managing cloud functions, enabling users to automate workflows more efficiently and leverage serverless architecture within their Kubernetes environments. Additionally, updates to the GraphQL schema and various components ensure that these new actions are fully supported and easily accessible.

* **Compatibility Matrix Update 2026-07-14** ([#3849](https://github.com/pluralsh/console/pull/3849)) by @app/github-actions

  > The compatibility matrix for EKS has been updated to include version v4.2.7-eksbuild.1, which is now compatible with Kubernetes versions 1.30 through 1.36. This enhancement ensures users can seamlessly integrate and manage their Kubernetes clusters with the latest EKS version, improving overall operational efficiency and compatibility.

* **Compatibility Matrix Update 2026-07-14** ([#3850](https://github.com/pluralsh/console/pull/3850)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions and support details for several Kubernetes add-ons, including KubeVirt, AWS Load Balancer Controller, Gatekeeper, and Kube Prometheus Stack. Notably, KubeVirt now supports multiple Kubernetes versions and provides links to its GitHub repository for easier access. Additionally, the AWS Load Balancer Controller has been updated to version 3.4.2, which introduces improvements in readiness gate handling and a new CLI tool for Ingress to Gateway migration, enhancing user experience and operational efficiency.

* **Extended-Support Matrix Update 2026-07-15** ([#3852](https://github.com/pluralsh/console/pull/3852)) by @app/github-actions

* **Compatibility Matrix Update 2026-07-15** ([#3854](https://github.com/pluralsh/console/pull/3854)) by @app/github-actions

  > The compatibility matrix has been updated to reflect new versions and end-of-life dates for several Kubernetes add-ons, including cert-manager, KServe, kube-prometheus-stack, and Vector. Notably, cert-manager now has an end-of-life date of July 8, 2026, and kube-prometheus-stack has been upgraded to version 87.16.1, which includes updates to embedded dependencies for improved functionality. Additionally, KServe version 0.18.1 introduces significant changes, such as a chart rename and namespace-scoped ModelCache support, while Vector version 0.57.0 focuses on enhancing security posture with potential breaking changes.

* **add GetDeploymentSettingsMinimal** ([#3855](https://github.com/pluralsh/console/pull/3855)) by @zreigz

This change simplifies access to critical deployment information, improving efficiency for users who need quick insights without the overhead of full deployment details.

* **feat: Enhance token count formatting** ([#3856](https://github.com/pluralsh/console/pull/3856)) by @maciaszczykm

  > Token count formatting has been enhanced to provide clearer and more intuitive representations. Counts below 1,000 are now displayed as '1K', while values near the million threshold are rounded appropriately to '1M', with one decimal place for values in the millions and billions. This improvement ensures users can quickly grasp token usage at a glance, enhancing the overall user experience in monitoring and managing resources.

## Bug Fixes 🐛

* **fix(controller): improve cloud connection handling** ([#3821](https://github.com/pluralsh/console/pull/3821)) by @floreks

  > Cloud connection handling has been enhanced to include an `UpdateCloudConnection` mutation, allowing users to modify existing cloud connection attributes directly. This improvement streamlines the management of cloud connections, enabling more efficient updates without the need to delete and recreate connections, ultimately enhancing user experience and operational efficiency in managing cloud integrations.

* **chore: Fix vulnerabilities** ([#3857](https://github.com/pluralsh/console/pull/3857)) by @maciaszczykm

  > Vulnerabilities in the codebase have been addressed by updating several dependencies, including critical packages such as `@graphql-codegen/add`, `@graphql-codegen/named-operations-object`, and `@graphql-codegen/plugin-helpers` to their latest versions. These updates enhance security and stability, ensuring a more robust development environment and reducing the risk of potential exploits. Users can expect improved performance and reliability in their applications as a result of these changes.

* **feat(logs): integrate text truncation in LogsFilters** ([#3863](https://github.com/pluralsh/console/pull/3863)) by @floreks

  > Text truncation has been integrated into the LogsFilters component, enhancing the user interface by ensuring that long field names are displayed neatly within a specified width. This improvement prevents overflow and maintains a clean layout, making it easier for users to navigate and select log filters without visual clutter.

* **Add the ability to respect all agentconfiguration fields at boot time** ([#3866](https://github.com/pluralsh/console/pull/3866)) by @michaeljguarino

  > The latest update enhances the Plural agent by ensuring that all configuration fields are respected at boot time. This improvement allows for more precise control over agent behavior, such as polling intervals and websocket connections, directly from the configuration settings, leading to better performance and adaptability in diverse deployment scenarios. Users can now customize their agent settings more effectively, improving the overall management of Kubernetes fleets.
