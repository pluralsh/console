# v0.12.36

## New Features 🎉

* **feat: Server side prompt queue** ([#3953](https://github.com/pluralsh/console/pull/3953)) by @maciaszczykm

  > The new server-side prompt queue feature enhances the workbench experience by allowing users to queue prompts for processing, improving workflow efficiency. Users can now see a visual representation of queued prompts, including their status and estimated next run time, directly within the workbench interface. This addition streamlines the management of job prompts, enabling better organization and prioritization of tasks in Kubernetes deployments.

* **More perf tweaks** ([#3961](https://github.com/pluralsh/console/pull/3961)) by @michaeljguarino

  > Performance improvements have been implemented across various components of the Plural Console, including adjustments to polling intervals and caching mechanisms. Notably, the stack polling interval has been increased from 30 seconds to 2 minutes, enhancing efficiency in resource management. Additionally, the agent's information cache TTL has been extended to 12 hours, which will reduce the frequency of redundant data fetching and improve overall responsiveness. These optimizations are crucial for users managing large-scale Kubernetes environments, ensuring smoother operations and faster response times.

* **feat: enabled deferred controller polling in deployment operator** ([#3962](https://github.com/pluralsh/console/pull/3962)) by @zreigz

  > Deferred controller polling has been enabled in the deployment operator, allowing users to configure whether the agent should perform an immediate poll upon startup. This feature is particularly beneficial for existing deployments, as it defers the initial polling for operators that have been running for over an hour, reducing unnecessary load on the system and optimizing performance during startup. Users can now manage polling behavior more effectively, enhancing the overall efficiency of their Kubernetes operations.

* **Compatibility Matrix Update 2026-08-05** ([#3965](https://github.com/pluralsh/console/pull/3965)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions of EKS and their associated compatibility with Kubernetes versions. Notably, versions such as `v4.0.10000020260803-eksbuild.1` and `v1.21.10001020260803-eksbuild.1` have been added, ensuring users can leverage the latest features and improvements in EKS while maintaining compatibility with Kubernetes versions 1.30 through 1.35. This update enhances the flexibility and reliability of deployments for users utilizing EKS in their Kubernetes environments.

* **Compatibility Matrix Update 2026-08-05** ([#3966](https://github.com/pluralsh/console/pull/3966)) by @app/github-actions

  > The compatibility matrix has been updated to reflect new Kubernetes version support for several addons. Notably, Argo CD has been upgraded to version 3.5.0, introducing significant features such as Helm 4 support, improved ApplicationSet management, and enhanced security with mTLS. Additionally, the BigBang addon now supports Kubernetes version 1.35, ensuring users can leverage the latest features and improvements in their deployments.

* **feat: Agent message two-turn updates** ([#3967](https://github.com/pluralsh/console/pull/3967)) by @maciaszczykm

  > The latest update introduces two-turn updates for agent messages, enhancing the user experience by allowing for more dynamic interactions within the AI agent run context. This change ensures that messages are merged by ID, maintaining conversation order while also displaying the runtime status of tools in use. As a result, users can now better track the progress and state of their agent interactions, leading to improved clarity and efficiency in managing AI-driven tasks.

* **fix(stacks): guard custom stack run name length** ([#3969](https://github.com/pluralsh/console/pull/3969)) by @app/plural-copilot

  > Custom stack run names are now validated to ensure they do not exceed 2,048 characters, preventing potential errors related to excessively long names. This enhancement improves user experience by enforcing a clear limit on name length, ensuring consistency and reliability when managing custom stack runs.

* **Step args length limit blocking custom run in mm** ([#3970](https://github.com/pluralsh/console/pull/3970)) by @JohnBlackwell

  > The maximum length for step arguments in custom runs has been increased to 2048 characters, allowing users to pass larger data sets or commands without encountering limitations. This enhancement is particularly beneficial for complex operations, such as Terraform imports, where extensive arguments may be necessary. Users can now create custom runs with more extensive configurations, improving flexibility and usability in their workflows.

* **Add repo mention type to workbenches** ([#3971](https://github.com/pluralsh/console/pull/3971)) by @michaeljguarino

  > Workbenches now support a new repository mention type, enhancing the functionality of the chatbots and input fields within the workbench interface. This addition allows users to reference repositories more effectively, streamlining workflows and improving collaboration when generating insights and automating tasks. This change is significant as it enhances user experience and efficiency in managing Kubernetes resources.

* **Compatibility Matrix Update 2026-08-06** ([#3972](https://github.com/pluralsh/console/pull/3972)) by @app/github-actions
