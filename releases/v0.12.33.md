# v0.12.33

## New Features 🎉

* **Compatibility Matrix Update 2026-07-22** ([#3891](https://github.com/pluralsh/console/pull/3891)) by @app/github-actions

  > The compatibility matrix for the EKS add-ons has been updated to include new versions for the eks-node-monitoring-agent, kube-state-metrics, and metrics-server, now supporting Kubernetes versions 1.30 through 1.36. This enhancement ensures users can leverage the latest features and improvements in these add-ons while maintaining compatibility with a broader range of Kubernetes versions, facilitating smoother deployments and upgrades.

* **Compatibility Matrix Update 2026-07-22** ([#3892](https://github.com/pluralsh/console/pull/3892)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions for several components, notably the kube-prometheus-stack, which now supports version 87.19.0. This update enhances visibility into scheduler performance by adding scraping for kube-scheduler resource metrics and upgrades Grafana to version 12.8.0, ensuring users benefit from the latest features and fixes. Additionally, the Elastic Agent has been updated to version 9.4.4, improving overall compatibility and functionality within the Kubernetes environment.

* **Add rate limiter to helm agent fetches** ([#3893](https://github.com/pluralsh/console/pull/3893)) by @michaeljguarino

  > A rate limiter has been added to the Helm agent fetches, enhancing the stability and performance of the deployment process by preventing excessive requests that could overwhelm the system. This improvement is crucial for maintaining consistent operation during high-demand scenarios, ensuring that users experience fewer disruptions and improved responsiveness when interacting with the Plural Console.

* **Compatibility Matrix Update 2026-07-23** ([#3896](https://github.com/pluralsh/console/pull/3896)) by @app/github-actions

  > The compatibility matrix for the Amazon SageMaker Hyperpod Observability addon has been updated to include version v1.0.10-eksbuild.2, which is now compatible with Kubernetes versions 1.30 through 1.35. This enhancement ensures users can leverage the latest features of the addon while maintaining compatibility with a broader range of Kubernetes versions, improving flexibility and usability in diverse environments.

* **Compatibility Matrix Update 2026-07-23** ([#3897](https://github.com/pluralsh/console/pull/3897)) by @app/github-actions

  > The compatibility matrix has been updated to reflect new versions and enhancements for several Kubernetes add-ons, including the AWS EBS CSI Driver, Amazon VPC CNI, Argo Workflows, and Kubescape Operator. Notably, the AWS EBS CSI Driver now supports Kubernetes versions 1.20 through 1.35, while the Amazon VPC CNI has been updated to version 1.22.4, ensuring compatibility with EKS 1.23. These updates are crucial for users to maintain operational efficiency and leverage the latest features and fixes in their Kubernetes environments.

* **Prep v0.12.33** ([#3898](https://github.com/pluralsh/console/pull/3898)) by @michaeljguarino

  > The release of version v0.12.33 includes an upgrade to the agent version (now v0.6.52) and increases the cache agent queue limit from 10 to 20, enhancing performance under load. Additionally, improvements were made to the manifest fetching logic, ensuring that HTTP errors are preserved during rate limit retries, which aids in better error handling and debugging. These changes collectively aim to improve the reliability and efficiency of the Plural Console's operations.

* **prep v0.12.33** ([#3899](https://github.com/pluralsh/console/pull/3899)) by @michaeljguarino

  > The agent version has been updated to v0.6.53, which includes a significant change to the default workqueue base delay, increasing it from 5 milliseconds to 1 second. This adjustment enhances the stability and performance of the deployment operator by allowing more time for processing tasks in the workqueue, ultimately improving the efficiency of Kubernetes operations. Additionally, new unit tests have been added to ensure the correct implementation of this configuration.
