# v0.12.47

## New Features 🎉

* **Update teams sink validation to accept post-2026 webhook hosts** ([#4112](https://github.com/pluralsh/console/pull/4112)) by @JohnBlackwell

  > The teams sink validation has been updated to accept webhook hosts that are valid post-2026, enhancing the flexibility of webhook integrations for Microsoft Teams. This change ensures that users can configure their notification sinks with URLs that comply with future standards, thereby improving the reliability and longevity of their integrations. Additionally, the update includes comprehensive tests to validate the new webhook URL formats, ensuring a robust implementation.

* **feat:  improve agent runtime cycle times** ([#4336](https://github.com/pluralsh/console/pull/4336)) by @zreigz

  > Agent runtime cycle times have been improved, enhancing the efficiency of the deployment operator. This update introduces new configuration options, such as `readOnlyRootFilesystem` and `Mise`, allowing users to better manage container security and bootstrap processes. These enhancements are crucial for optimizing resource utilization and streamlining the setup of coding environments within Kubernetes.

* **feat: Add monitoring tab and improve workflows** ([#4353](https://github.com/pluralsh/console/pull/4353)) by @maciaszczykm

  > A new monitoring tab has been added to the Plural Console, enhancing user workflows by providing a dedicated space for managing and visualizing service monitors. This feature allows users to create and edit monitoring configurations more efficiently, improving observability of their Kubernetes services. Additionally, various workflow improvements have been implemented to streamline CI processes, ensuring a smoother development experience.

* **feat: add k8sObjMeta for lua and python** ([#4380](https://github.com/pluralsh/console/pull/4380)) by @zreigz

  > The addition of `k8sObjMeta` for Lua and Python enhances the deployment operator's capabilities by allowing users to retrieve Kubernetes object metadata directly within their scripts. This feature simplifies the process of accessing critical information, such as namespace and labels, thereby improving the efficiency of automation tasks and reducing the complexity of managing Kubernetes resources. With this update, users can now seamlessly integrate Kubernetes metadata into their workflows, streamlining operations and enhancing overall productivity.

* **Prebake improvements** ([#4385](https://github.com/pluralsh/console/pull/4385)) by @michaeljguarino

  > Improvements have been made to the repository prebake process, including updates to the Docker images used for building and pushing, which now utilize Docker Hub instead of GitHub Container Registry. This change enhances accessibility and consistency in image management, ensuring that users can more easily leverage the latest precompiled resources for their Kubernetes deployments. Additionally, the documentation has been updated to reflect these changes, providing clearer guidance on configuring and utilizing the prebake functionality.

* **Repository Image Prewarming** ([#4386](https://github.com/pluralsh/console/pull/4386)) by @michaeljguarino

  > The latest update introduces repository image prewarming, enhancing the deployment process by allowing images to be preloaded before they are needed. This feature optimizes startup times for applications by ensuring that necessary images are readily available, thereby improving overall performance and user experience during deployments. Additionally, new configuration options for OAuth token exchange have been added, providing greater flexibility and security in managing authentication.

* **Compatibility Matrix Update 2026-09-22** ([#4387](https://github.com/pluralsh/console/pull/4387)) by @app/github-actions

  > The compatibility matrix for EKS has been updated to include support for the new version `v1.47.10000020260919-eksbuild.1`, ensuring compatibility with Kubernetes versions 1.35, 1.34, and 1.33. This update is crucial for users looking to leverage the latest EKS features while maintaining compatibility with their existing Kubernetes deployments.

* **Compatibility Matrix Update 2026-09-22** ([#4388](https://github.com/pluralsh/console/pull/4388)) by @app/github-actions

  > The compatibility matrix has been updated to include new versions for several integrations, notably `external-secrets` (v2.11.0), `istio` (v1.31.1), and `kuberay-operator` (v1.7.1). Key enhancements include the addition of a `global.imageRegistry` value in the `external-secrets` Helm chart for improved image management, and updates to the `kuberay-operator` that disable live-cluster support by default to prevent unintended proxying. These updates ensure better compatibility and functionality for users managing Kubernetes deployments.
