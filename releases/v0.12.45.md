# v0.12.45

## New Features 🎉

* **feat: Show pod requests and limits on component/service metrics views** ([#4337](https://github.com/pluralsh/console/pull/4337)) by @maciaszczykm

  > Pod requests and limits are now displayed on the component and service metrics views, providing users with enhanced visibility into resource allocation. This update allows users to better understand the resource requirements of their Kubernetes workloads, facilitating more informed capacity planning and optimization decisions.

* **feat(console): sidebar control for new console builds** ([#4347](https://github.com/pluralsh/console/pull/4347)) by @wailingwombat

  > A new sidebar control has been introduced in the Plural Console, allowing users to easily check for and apply updates to the console directly from the sidebar. This feature enhances user experience by providing a streamlined way to manage application updates without the need for disruptive notifications or to navigate away from the current workflow. The previous toast notification for updates has been removed, consolidating update management into a more user-friendly interface.

* **Compatibility Matrix Update 2026-09-17** ([#4348](https://github.com/pluralsh/console/pull/4348)) by @app/github-actions

  > The compatibility matrix for various EKS add-ons has been updated to include new versions and their supported Kubernetes versions. Notably, several add-ons such as cert-manager, metrics-server, and kube-state-metrics now support compatibility with Kubernetes versions down to 1.30, enhancing user flexibility in managing their Kubernetes environments. This update ensures that users can leverage the latest features of these add-ons while maintaining compatibility with older Kubernetes versions.

* **Skill update automation** ([#4349](https://github.com/pluralsh/console/pull/4349)) by @michaeljguarino

  > The skill update automation feature has been enhanced to improve the management of Git credentials within the deployment operator. Notably, the configuration now defaults to a specified username when none is provided, ensuring seamless integration with services like Bitbucket Data Center. Additionally, the automation process has been refined to guide users in utilizing the `updateAgentRunAnalysis` tool effectively, enhancing the overall user experience and reducing potential errors during analysis tasks.

* **Compatibility Matrix Update 2026-09-17** ([#4350](https://github.com/pluralsh/console/pull/4350)) by @app/github-actions

  > The compatibility matrix has been updated to reflect new versions and enhancements for several key components, including Cilium, Argo CD, and the Kube Prometheus Stack. Notably, Cilium has introduced version 1.20.2, which improves Helm chart flexibility and adds new health probing capabilities for the cilium-envoy DaemonSet. Additionally, Argo CD has been upgraded to version 3.5.3, ensuring better accuracy in application synchronization and minor UI enhancements. These updates are crucial for maintaining compatibility and improving the reliability of your Kubernetes deployments.

* **customizable migration command for plural chart** ([#4354](https://github.com/pluralsh/console/pull/4354)) by @michaeljguarino

  > The migration command for the Plural chart has been made customizable, allowing users to specify their own migration commands in the `values.yaml` file. This enhancement provides greater flexibility for users to tailor migration processes according to their specific needs, improving the overall usability of the Plural deployment. Additionally, the chart version has been updated to 0.10.111, ensuring users benefit from the latest improvements and fixes.

* **Compatibility Matrix Update 2026-09-18** ([#4355](https://github.com/pluralsh/console/pull/4355)) by @app/github-actions

  > The compatibility matrix for EKS has been updated to include new versions and their supported Kubernetes versions. Notably, versions v2.0.10000020260915-eksbuild.1, v4.5.10000020260916-eksbuild.1, and v1.47.10001020260916-eksbuild.1 are now compatible with Kubernetes versions 1.30 through 1.35. This update ensures users can leverage the latest EKS features while maintaining compatibility with their Kubernetes clusters.

* **Compatibility Matrix Update 2026-09-18** ([#4356](https://github.com/pluralsh/console/pull/4356)) by @app/github-actions

  > The compatibility matrix has been updated to reflect the latest versions of various components, including a new chart version for Argo CD (10.9.2) and Argo Rollouts (2.43.2), as well as the introduction of Big Bang version 3.33.0. This update enhances stability and introduces new features while also highlighting potential breaking changes that may require validation before deployment, ensuring users can maintain compatibility and performance in their Kubernetes environments.

* **Prep v0.12.45** ([#4358](https://github.com/pluralsh/console/pull/4358)) by @michaeljguarino

  > The release of version v0.12.45 introduces significant enhancements to the Plural Console, including the addition of automation features for skill-update jobs within the workbench, allowing users to automatically create jobs based on low-scoring evaluations. This update also refines access controls across various AI and deployment functionalities, ensuring that users have the appropriate permissions for reading and writing actions. These improvements enhance user experience by streamlining workflows and reinforcing security measures.


## Bug Fixes 🐛

* **fix(stacks): support preserving explicit empty container lists** ([#4351](https://github.com/pluralsh/console/pull/4351)) by @floreks

  > Support for preserving explicit empty container lists in job specifications has been implemented, allowing users to differentiate between omitted and explicitly empty container lists. This change enhances the clarity and control over job configurations, ensuring that users can specify their intent more accurately when defining Kubernetes jobs. The update is particularly beneficial for users managing complex deployments, as it prevents unintended behavior caused by defaulting to nil values.

* **fix: Restore compatible GraphQL codegen versions** ([#4352](https://github.com/pluralsh/console/pull/4352)) by @maciaszczykm

  > Compatible versions of the GraphQL code generation tools have been restored, specifically downgrading `@graphql-codegen/cli` to version 6.3.1 and adjusting related dependencies. This change ensures better stability and compatibility within the Plural Console, addressing issues that may have arisen from using newer versions that were not fully supported. Users can expect improved functionality and fewer errors when generating GraphQL code.
